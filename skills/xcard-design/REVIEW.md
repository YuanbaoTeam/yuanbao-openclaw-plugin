# XCard 视觉审查

## 评分门禁

每项 0–2 分，总分 20。低于 16 不交付；任一“硬失败”存在时不计总分，先修复。

1. **任务清晰**：第一眼能否理解卡片目的？
2. **视觉焦点**：是否只有一个主焦点？
3. **信息层级**：主、辅、弱三层是否可辨？
4. **模式与构图**：是否选对交互组件和分组，而不是套用通用卡片模板？
5. **间距节奏**：相关项靠近、区块拉开，且使用有限尺度？
6. **排版**：variant、行数、长文案和数字单位是否稳定？
7. **色彩克制**：语义 token 正确，强调色没有泛滥？
8. **操作主次**：是否最多一个主操作，点击面和状态明确？
9. **移动端适配**：窄屏无溢出、逐字换行和过小触控区？
10. **Apple 式完成度**：是否清晰、安静、精确、内容优先，而非装饰堆叠？

每项判断：

- `2`：明确满足，且有产物或截图证据。
- `1`：基本满足，但存在一个具体可改进点。
- `0`：不满足、无法判断或依赖未经验证的 renderer 行为。

## 硬失败

- 使用 Catalog 未声明的组件、属性、style 或 token。
- 多个同权重主按钮，用户无法判断下一步。
- 文字、日期、价格、状态或按钮在窄屏明显溢出/碎裂。
- 只靠颜色表达成功、失败、选择或禁用状态。
- 为美观虚构业务数据、图片、能力或操作。
- 用一组高权重 Button 模拟本应由 Choice、Picker、Stepper、Pager 或 Switcher 承担的交互。
- 视觉修改破坏 action、DataModel 路径、组件引用或 103 更新稳定性。
- 没看真实截图却声称视觉已在 App 验收。

## 静态审查顺序

1. 先判断任务属于浏览、选择、配置、对象切换、分步问卷、持续交互或纯展示。
2. 检查组件是否匹配任务：轮播用 Pager，富选择用 ChoiceGroup，固定枚举用 ChoicePicker，
   数量用 Stepper，对象联动用 ItemPicker + Switcher，动态重复用 List。
3. 画出从 `root` 开始的阅读顺序。
4. 标出所有 h1–h5、品牌色、功能色、容器底色和可点击组件。
5. 检查是否出现多个焦点、重复文案或无意义 CTA。
6. 对所有 Row/Grid 使用最长合理业务文案做窄屏推演。
7. 检查默认、选中、禁用、错误、空态和完成态。
8. 检查自由卡片更新前后主体 id、尺寸和位置是否稳定。
9. 做一次减法：删除不影响任务完成的最低价值元素。

## 模式专项检查

- **富选项**：整行点击面是否明确；图片比例、标题、描述和选中状态是否逐行对齐？
- **轮播**：是否一页一个焦点、图片比例稳定、存在页码反馈且文字对比度足够？
- **对象切换**：Picker 是否可读且可滚动；Switcher 更新后标题和整体结构是否稳定？
- **多步骤问卷**：是否一屏一题，有明确进度和前后导航，且只在最后一步提交？
- **商品配置**：固定规格是否使用 Picker、数量是否使用 Stepper、当前配置是否有摘要？
- **列表**：重复项是否保持相同字段关系，是否避免每行嵌套重 Card？
- **纯信息卡**：没有真实下一步时是否克制地省略按钮？
- **双操作区**：是否只有一个 `primary`，次操作使用 `default` 或更弱层级？

## 截图审查顺序

1. **眯眼测试**：缩小或模糊后是否仍能看到焦点和主操作？
2. **灰度测试**：去掉颜色后层级是否仍由排版与间距成立？
3. **边缘扫描**：左右边界、文本基线、按钮宽高是否整齐？
4. **密度检查**：是否存在拥挤区和无意的大块空洞？
5. **状态对比**：操作前后变化是否明显且布局稳定？
6. **双主题检查**：light/dark 下对比、图片边缘和弱文本是否正常？

发现问题时必须写成“位置 + 原因 + 具体修改”，不能只写“感觉不够高级”。

## 借鉴来源

本 Skill 提炼方法，不复制其 Web/CSS 实现：

- `kasonye/ui-aesthetics-skill`：组件精度、状态、层级与克制的深度系统。
- `wondelai/skills/refactoring-ui`：先层级与留白、后色彩装饰的系统化检查。
- `dtsong/agentic-council/visual-audit`：基于截图证据的层级、间距、排版和色彩审查。
- `pbakaus/impeccable`：生成后的 arrange/polish 减法与一致性检查。
- Apple Human Interface Guidelines：clarity、deference、depth 与平台一致性。

外部来源只提供设计判断。任何 CSS、字体、阴影、动画和组件建议都必须重新映射到
元宝 XCard Catalog/token；无法合法映射时舍弃。
